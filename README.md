# Finance App — личные финансы

Учебное приложение на Java для учёта доходов и расходов. У каждого пользователя свой кошелёк с историей операций, категориями и бюджетами. Через терминал можно узнать баланс, посмотреть остаток лимита по категории и сохранить отчёт в текстовый файл.

## Запуск

Установите JDK 26 и откройте терминал в корне проекта. Для запуска используется Gradle Wrapper из репозитория.

| Действие | macOS / Linux | Windows PowerShell |
|---|---|---|
| Запустить приложение | `./gradlew --console=plain run` | `.\gradlew.bat --console=plain run` |
| Запустить тесты | `./gradlew test` | `.\gradlew.bat test` |

После запуска введите `help`, чтобы увидеть список команд.

## Пример работы

Пример для нового пользователя `demo`. Введите команды по очереди в консоли приложения.

```text
register demo demo1234
login demo demo1234
category income Зарплата
category expense Еда
income 5000 Зарплата Выплата за неделю
budget Еда 1000
expense 800 Еда Покупка продуктов
balance
stats Еда
```

Команда `balance` покажет `4200.00`. В категории `Еда` потрачено `800.00` из `1000.00`, остаток — `200.00`. При добавлении расхода приложение предупредит, что использовано 80% бюджета. Отдельные уведомления появятся при исчерпании лимита, его превышении и когда общие расходы превысят доходы.

Теперь можно переименовать категорию и сохранить отчёт:

```text
rename expense Еда Продукты
history
report reports/demo.txt Продукты
exit
```

В истории покупка будет указана под именем `Продукты`. Бюджет и остаток сохранятся. При следующем запуске достаточно ввести `login demo demo1234`, чтобы продолжить работу.

## Команды

| Действие | Команды |
|---|---|
| Регистрация и вход | `register <логин> <пароль>`, `login <логин> <пароль>` |
| Создание категории | `category income <название>`, `category expense <название>` |
| Просмотр и переименование категорий | `categories`, `rename <тип> <старое> <новое>` |
| Добавление операции | `income <сумма> <категория> [описание]`, `expense <сумма> <категория> [описание]` |
| Установка или изменение лимита расходов | `budget <категория> <лимит>` |
| Баланс и история операций | `balance`, `history` |
| Полная статистика или выборка по категориям | `stats`, `stats <категория1> <категория2> ...` |
| Запись отчёта в файл | `report <файл> [категории...]` |
| Справка | `help` |
| Выход с сохранением кошелька | `logout` — выйти из аккаунта, `exit` — завершить приложение |

Тип категории — `income` или `expense`. Название состоит из одного слова, регистр учитывается. Категорию нужно создать до первой операции. Сумма должна быть положительной, допускается до двух знаков после точки или запятой, например `150.50` или `150,50`.

## Хранение данных

Во время работы пользователи и кошельки хранятся в памяти. Файлы создаются относительно папки запуска приложения.

- `data/users.json` содержит логины и хеши паролей. Обновляется при регистрации.
- `data/wallets/<логин>.json` содержит категории, бюджеты и операции одного пользователя. Кошелёк сохраняется при `logout` или `exit` и загружается при первом входе пользователя после запуска приложения.
- Текстовый отчёт сохраняется по пути из команды `report`. Для отчётов удобно использовать отдельную папку, например `reports/demo.txt`.

## Структура проекта

| Путь | Назначение |
|---|---|
| `src/main/java/Main.java` | Точка входа. Создаёт хранилище и сервисы, запускает CLI. |
| `src/main/java/cli/` | Цикл чтения команд, разбор аргументов и вывод сообщений. |
| `src/main/java/model/` | Пользователь, кошелёк, операции дохода и расхода, работа с денежными суммами. |
| `src/main/java/service/` | Авторизация, операции с кошельком, статистика, уведомления и отчёты. |
| `src/main/java/repository/` | Реестр пользователей в памяти, сохранение и загрузка JSON с помощью Gson. |
| `src/main/java/util/` | Проверка ввода и хеширование паролей. |
| `src/test/java/` | Модульные и интеграционные тесты на JUnit 5. |

## Тестирование и CI

В проекте 16 тестов. Модульные тесты проверяют кошелёк и валидацию сумм. Интеграционные тесты запускают приложение во временной папке и проверяют команды CLI, изоляцию пользователей, уведомления, статистику и восстановление кошелька после перезапуска.

После `./gradlew test` HTML-отчёт доступен в `build/reports/tests/test/index.html`.

При `push` и `pull_request` GitHub Actions запускает `./gradlew check` на Ubuntu с JDK 26. Конфигурация находится в `.github/workflows/ci.yml`.
